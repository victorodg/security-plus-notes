## The Three Pillars: CIA Triad

Cybersecurity has three core goals, known as the **CIA Triad**:

| Goal | Definition |
|---|---|
| **Confidentiality** | Prevents the unauthorized disclosure of information |
| **Integrity** | Prevents the unauthorized alteration of information or systems |
| **Availability** | Ensures authorized users can access information and systems when needed |

---

## Ensuring Confidentiality

**Encryption**
Scrambles data to make it unreadable by unauthorized personnel. Only someone with the correct key can convert it back into readable form.

**Access Controls**
Confidentiality relies on controlling *who* can get to data in the first place. This happens in three stages:

1. **Identification** — the user claims an identity, typically with a unique username
2. **Authentication** — the user proves that claimed identity (e.g., with a password, biometric, or token)
3. **Authorization** — once verified, the system grants or restricts access to resources based on permissions

---

## Providing Integrity

**Hashing**
A hash is an alphanumeric string generated by running data through a hashing algorithm. It produces a fixed-length, irreversible output — you can't reverse a hash back into the original data.

Hashing is used to verify that data hasn't been modified:
- Confirming a downloaded file matches the original (comparing hash values)
- Detecting unauthorized changes to files or system data during transfer or storage

## Increasing Availability

**Redundancy and Fault Tolerance**
Redundancy means adding duplication to critical systems so that if one component fails, another takes over. The goal is to eliminate every **single point of failure (SPOF)** — any one component whose failure would take down the whole system.

Common types of redundancy:

- **Disk redundancy** — using RAID (Redundant Array of Independent Disks) configurations so a single failed drive doesn't cause data loss
- **Server redundancy** — running multiple servers (e.g., in a failover cluster) so if one goes down, another takes over automatically
- **Network redundancy** — having multiple network paths or ISPs so connectivity survives if one link fails
- **Power redundancy** — using backup power sources like UPS (Uninterruptible Power Supply) units and generators to keep systems running through outages

**Scalability and Elasticity**
- **Horizontal scaling** — adding more servers to handle increased load (e.g., going from 3 web servers to 5)
- **Vertical scaling** — adding more resources (memory, CPU) to an existing server
- **Elasticity** — automating scalability so the system adds/removes resources on its own based on demand

**Patching**
Keeping systems updated is another key part of availability. Unpatched software bugs cause security vulnerabilities and stability issues (crashes, downtime).

**Resiliency**
Resiliency methods allow systems to self-heal or recover from faults automatically, minimizing downtime when something does go wrong.

---

## Quick Recap
- **C**onfidentiality → Encryption + Access Controls (Identification, Authentication, Authorization)
- **I**ntegrity → Hashing
- **A**vailability → Redundancy, Scalability/Elasticity, Patching, Resiliency
